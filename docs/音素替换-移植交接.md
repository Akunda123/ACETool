## 1 目标与验收

做一件事：**给一批 ACE 音符，把它们的音素（发音）挑着换掉**，并像 SV 那样给出「这是什么类别、例子是什么」的候选。

验收三条：

1. 选中若干音符 → 能读到每个音符**当前生效的音素**，并标明它是 **override 还是默认**（`isOverride`）；
2. 每个音素位置能选候选，候选里有**类别 + 示例**；
3. 干跑能给出逐音符对照（before → after、几处改、会不会**冻结**成 override），真写后可 `phoneme reset-override` 一键回退。

## 2 源脚本现在做什么

### 2.1 数据（三块，全部按语言索引）

| 变量 | 内容 | 用途 |
|---|---|---|
| `Consonants0[lang]` | 该语言辅音全集 | 判"这个 token 是辅音还是元音"；辅音候选按**字母近似** |
| `Vowels0[lang]` | 元音参考顺序 | 候选排序 |
| `Vowels[6][lang]` | 元音分成 6 个"族" | 元音候选 = **同族并集**（Jaccard 思路） |

### 2.2 流程

```
取选中音符（没有就整组）
  → SV.getPhonemesForGroup() 拿每个音符的实际发音串（含 T2P 默认）
  → 逐音符、逐 token：
        是辅音 → 按字母近似给出候选
        是元音 → 找出它属于哪个族 → 该族并集
     弹「音素替换」对话框（每个 token 一个 ComboBox + 一个"跨语种匹配"勾选）
        勾了跨语种 → 再弹第二个对话框（6 个语种各一列候选）
  → 汇总成新音素串 → 逐个 setPhonemes()
```

### 2.3 目前版本的关键设计（移植时要保留的）

- **双数据集按宿主版本选**：SV1 / SV2<2.3 只有 6 语种、只有老 X-SAMPA 写法；SV2≥2.3 有 10 语种 + 简化音素。判据 `hostVersionNumber >= 131329`（SV2）、`>= 131840`（2.3.0）。**ACE 没有这个分叉**，见 §4.3。
- **候选项 = 定宽拼接**：`padW(token, 7) + 类别 + " · " + 示例`，显示成两列（`zh     塞擦音 · 之 zh ir`）。
- **显示串 ↔ 裸 token 用映射表**（`DISP2TOK`），**不拆字符串**还原；匹配/写回一律用裸 token。
- 类别/示例来自 SV 官方音素表（2.3.0）+ 老表合并补齐（`AU/@U` 这类被 2.3.0 删掉的写法）；本语言查不到时跨语言回退。
- 原文件备份：`音素替换.js.bak-202611021341`（原始）、`.bak-before-display`、`.bak-before-pad`。

### 2.4 两个**不要照搬**的毛病

1. **子串替换**（`批量替换音素.js` 的老问题，已在 ACETool 的 `phoneme.replace` 里改成按 token）。移植这版时同样**按 token**，ACE 对音素是"要么合法要么拒"。
2. **"先算好整串再一把写"**：ACE 的 `phoneme set` **一次只收一个音符**，N 个音符要 N 次调用，且每次都能被 `USER_BUSY` / `STALE_WRITE` 打断 ⇒ 要设计成**逐音符提交 + 汇总报告**，不是一次性组包。

## 3 ACE 侧等价能力（已核对 CLI 帮助）

| SV 概念 | ACE 命令 | 说明 |
|---|---|---|
| `getPhonemesForGroup()` | `phoneme list --note <UUID>... [--with-timings]` | 返回 `phonemes / headConsonants / vowels / tailConsonants / isOverride / defaultPhonemes / timingKinds / overrideLegal`；**必须给 scope**（`--note` 或 `--clip`+range） |
| `setPhonemes()` | `phoneme set --note <UUID> --phoneme <SYM>...` | **一个音符一次**；符号必须在该音符语言的 inventory 里；**空列表被拒**（清 override 用 `phoneme reset-override`） |
| 语言合法集 | `phoneme inventory --language "Chinese"` | 返回 `{language, consonants[], vowels[]}`（现有 `phonInventory()` 就在用） |
| 默认发音参考 | `phoneme g2p --language <L> --grapheme <TEXT>...` | 与 `defaultPhonemes` **不一定相同**（默认是冻结的，g2p 是现算的） |
| 恢复默认 | `phoneme reset-override --note <UUID>...` | 相当于把音符交还引擎推导 |
| 清时间 | `phoneme reset-timing` / `reset` | 音素时机相关的另一套概念，别和 override 混 |
| 辅音时长 | `phoneme set-consonant-timing --note --index --length` | 支持 `--dry-run` |
| 音节边界 | `phoneme move-boundary --note --index --to <秒>` | 0-based，`--index` 来自 `phoneme list --with-timings` |

**写操作的通用护栏（ACE 有，SV 没有，务必用上）**：

- `--if-match <fingerprint>`：**陈旧写守卫**（读一次拿指纹，写时带上；变了就 `STALE_WRITE`）；
- `--dry-run`：只算不写、不动撤销栈；
- `-y`：跳过确认；
- `--wait-busy 5s`：用户正在操作时等待而不是直接 `USER_BUSY`；
- 退出码/信封：`acecli.Client.Run/Read` 已经包了 `Envelope` + `OK()`。

## 4 移植设计（建议）

### 4.1 放哪

- 新工具 ID 建议 **`phoneme.pick`**（Category 仍 `音素`），与现有 `phoneme.replace`（`internal/tools/phonops.go`）并列；**不要塞进同一个工具**——两者交互模型不同（一个两输入框，一个逐 token 选）。
- 复用已有件：`phonInventory()`（phonops.go）、`noteScopeView`/范围解析（`internal/tools/scope.go`）、`readJSON`/`Client.Read`（`internal/acecli`）。
- 注册照 `register(&Tool{ID, Category, Title, Desc, Kind: KindWrite, Params, Plan, Apply})`（见 `internal/tools/registry.go` 与 phonops.go 的 `init()`）。

### 4.2 UI：需要**专用面板**（不是 schema 表单）

schema 表单放不下"每个 token 一个带候选的下拉 + 类别/示例"。ACETool 已有两个专用面板（`find.notes`、`color.cycle`）可照抄：

- 后端：在 `panel_api.go` 加端点（读现状 / 给候选 / 干跑 / 提交），
- 前端：面板里一列音符、每个 token 一个 `<select>`，选项文本 = `padW(token,7) + 类别 + " · " + 示例`（与 SV 版一致），
- 自检：`devtools/panelcheck` 增加一节（照它测「批量替换音素」那节的结构）。

### 4.3 与 SV 版的**三处必须不同**

1. **没有宿主版本分叉**：ACE 只有一套 inventory ⇒ 删掉 `SV1_DATA/SV2_DATA` 与 `isSV230` 那套逻辑。
2. **没有"两套写法"**：不需要 X-SAMPA↔简化音素映射；候选直接用 `inventory` 里的符号。
3. **override 语义要做成一等公民**：ACE 对"没被改写过的音符"写音素 = **把默认发音冻住**（`isOverride` 变 true）。SV 版没有这个概念 ⇒ 面板上必须：
   - 标出哪些音符会被**冻结**（计入 `willFreeze`，phonops.go 已有此概念，照搬）；
   - 给「恢复默认」按钮（`phoneme reset-override`）。

### 4.4 候选算法怎么来

SV 版依赖"6 族 + 字母近似"的人工分类，ACE 侧没有这份数据。两条路：

- **A（推荐，先做）**：类别/示例**自建一张元数据表**（可复用 SV 的 2.3.0 音素表里同名字符的类别与例词，按语言索引），候选 = 同类别 + 字母近似（照 SV 的辅助逻辑，改数据源即可）；
- **B（后做）**：用 `phoneme g2p` 反查"引擎更可能给这个字什么音素"，作为候选排序的先验。

> 未验证：`phoneme inventory` 的 JSON 是否带 `category/example`。现有 `phonInventory()` 只解析 `language/consonants/vowels`，若无则必须走 A。

## 5 分阶段实施（每步可单独验收）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1 只读面板** | `phoneme.pick` 读出选中音符的 `phonemes / isOverride / defaultPhonemes`，列表展示；标出 override | 面板能列出与 ACE 钢琴卷帘一致的内容；override 音符有标记 |
| **P2 候选 + 干跑** | 每个 token 一个下拉（候选带类别/示例）；干跑输出 before→after、`willFreeze`、计划命令（含 `--if-match` 指纹） | 干跑不写任何字节；`willFreeze` 与实际相符 |
| **P3 真写 + 回退** | 逐音符 `phoneme set`（带 `--if-match`、`--wait-busy 5s`）；失败汇总（`STALE_WRITE`/`USER_BUSY`/符号非法）；「恢复默认」调 `reset-override` | 写后读回一致；`STALE_WRITE` 时不半途而废（逐条报） |

## 6 风险与未验证

- **ACE 必须在线**才能读工程；CI/单测只能覆盖纯逻辑（候选、拼接、指纹传递），真机验收不可省。
- **N 次调用**：一个片段几百音符就是几百次 CLI 进程，性能与中断都要考虑（参考 `xcopywithin.go` 批量写的那种分段/取消处理）。
- **`inventory` 是否带类别/示例**（见 §4.4）——决定候选数据是"现成"还是"自建表"。
- **timing 与 override 是两个字段**：只改音素不会动 timing；若用户之前用过"重置音素时机"，`timingKinds` 会非空，面板要如实展示而不是吞掉。
- **SV 版的显示细节可以照抄**：定宽拼接（CJK 算 2 格）、`DISP2TOK` 映射表还原、类别/示例缺失时的跨语言回退、以及“没信息就只显示 token”的诚实降级。

## 8 探测结果（2026-11-03，ACE 2.1.9 在线）

```json
{"language":"Chinese","consonants":[23 个],"vowels":[74 个],
 "phoneticsHints":{"a":"ä","ai":"äi̯",...},   // 音素 → IPA
 "contextSupported":false,"defaultGrapheme":"啦","defaultPhonemes":[...]}
```

`phoneticsHints` 只有 IPA；`category/example` 字段不存在。

### 8.2 有官方表：`timedomain-tech/ACE_phonemes`

| 文件 | 内容 |
|---|---|
| `phoneme_mapping.md` | ACE 音素 ↔ IPA ↔ 四分类（Vowel / Semivowel / Consonant / Vocalic Consonant），英/西/中/日 |
| `phonemes.md` | 各语言 heads / tails 清单 |

已抓进 `internal/phoneme/source/`；另有官方文档站「音素字典」页（docs.acestudio.ai/…/annexe/phoneme-dictionary，本机访问被阻，待确认是否带例词）。

### 8.3 落地方式（已实现）

- `devtools/gen_phoneme_table.py`：解析官方 mapping → `internal/phoneme/table.go`（含 IPA、四分类、按 IPA 推断的发音方式、例词）；
- 例词：优先取 SV 官方音素表**同符号**的例词（英文 ARPABET 命中率高），没有就留空；
- 官方表对中文韵母覆盖不全（74 个缺 24 个，主要是儿化与少见韵母）⇒ `phoneme.Describe` 用 CLI 的 IPA + 符号规律兜底；
- 覆盖率测试：`internal/phoneme/inventory_test.go` 断言 zh/eng/jp 三个 inventory 里**每个符号**都能拿到类别/发音方式（当前全过）。
